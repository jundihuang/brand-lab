# BrandLab v0.3 多市场翻译迭代计划

- 版本：v0.3.0
- 状态：Planning
- 前置版本：v0.2.1
- 目标：支持“检查已有市场翻译 → 生成修复建议 → 人工确认 → 安全回写”，并支持新增市场后的自动翻译 / localization workflow。

## 1. 迭代结论

现有 BrandLab 已有 `markets` 配置、`target_locale` job 和基础内容审计，但还不是一个完整的多市场翻译产品。

本轮要补齐三个能力：

1. **Market Registry**：把 market、locale、source strategy、review policy、audit policy 定义清楚。
2. **Existing Translation Audit**：读取 Shopify 已有翻译；有源内容时做配对体检，没有源内容时做目标内容独立体检。
3. **Market Onboarding**：新增市场时自动判断是翻译、localization，还是不需要处理。

完整流程不是只读流程。只有“发现与体检”是只读；修复和回写必须经过单独审批。

## 2. 用户场景

### 场景 A：检查 MX 已有翻译

用户说：

```text
检查 MX 市场现有翻译。
```

BrandLab 先确认审计模式。

### 模式 A1：有源内容

如果 Shopify base locale、用户上传文件或历史 translation job 中能找到英文源内容：

```text
确认店铺和 MX locale
→ 查找可用的源内容
→ 读取 Shopify 已发布的 MX 翻译
→ 按 resource + field 配对
→ 执行规则审计
→ 可选执行 AI Review
→ 生成 MX 翻译体检报告
→ 标记 keep / fix / retranslate
```

### 模式 A2：没有源内容

如果这是一个现成 MX 店铺，已经没有英文源内容：

```text
确认店铺和 MX locale
→ 读取 Shopify 已发布的 MX 翻译
→ 读取可用的 product context、metafields、collection context
→ 执行目标内容独立规则审计
→ 可选执行目标内容 AI quality review
→ 生成 MX 翻译体检报告
→ 标记 keep / rewrite / localize / manual_review
```

没有源内容时，BrandLab 不应声称能确认“漏译、多译、错译”。报告必须显示 `audit_mode=target_only`，并列出无法校验的语义项。

检查阶段不修改 Shopify。

用户确认修复后，才进入：

```text
创建 correction job
→ 翻译或局部改写
→ deterministic validation
→ review packet
→ 人工 approve
→ 生成回写计划
→ 人工确认执行
→ read-back verification
```

### 场景 B：新增 US 市场

用户说：

```text
新增 US 市场，语言是 English。
```

BrandLab 执行：

```text
检查 Shopify market / language / locale
→ 判断源语言与目标语言
→ 更新 brand.yaml
→ 创建或继承 guideline / glossary
→ 扫描可翻译内容
→ 生成 market content plan
```

如果 source language 是 `en`，US 目标语言也是 `en`，不创建 English-to-English 翻译任务，改为 localization audit：

```text
SEO 检查
→ 法务 / 合规措辞检查
→ 品牌语气检查
→ 地区差异检查
→ 输出 localization recommendations
```

如果未来新增 FR、DE、JP 等市场，则走标准翻译 workflow：

```text
scan source content
→ create market translation jobs
→ translate
→ validate
→ review
→ approve
→ export / safe writeback
```

## 3. Market Registry 设计

`brand.yaml` 从简单的 market/locale 列表升级为市场注册表。

```yaml
source:
  default_locale: en

markets:
  - id: MX
    market: MX
    locale: es-MX
    shopify_locale: es
    enabled: true
    source_strategy: base
    translation_mode: auto_with_review
    review_required: true
    audit_policy: standard

  - id: US
    market: US
    locale: en-US
    shopify_locale: en
    enabled: true
    source_strategy: base
    translation_mode: localization_only
    review_required: true
    audit_policy: seo_and_legal
```

字段约定：

| 字段 | 说明 |
|---|---|
| `id` | BrandLab 内部市场 ID，用于跨市场报告和 guideline 匹配。 |
| `market` | 业务市场代号，例如 `MX`、`US`。 |
| `locale` | BrandLab 使用的 BCP 47 locale。 |
| `shopify_locale` | Shopify Admin 中实际可用的 locale。 |
| `source_strategy` | `base`、`bridge`、`existing_translation`。 |
| `translation_mode` | `translation`、`localization_only`、`manual_only`。 |
| `review_required` | 是否必须人工审核。 |
| `audit_policy` | 使用的审计策略，例如标准、SEO、法务。 |
| `audit_mode` | `auto`、`paired_source` 或 `target_only`。`auto` 表示优先找源内容，找不到时降级为独立体检。 |

禁止只用 locale 推导 market。多个市场可能共用近似语言，必须允许显式选择。

## 4. Existing Translation Audit

新增已有翻译体检能力，与当前 `audit_content.py` 区分。

体检分为两种模式：

| 模式 | 触发条件 | 能校验的范围 |
|---|---|---|
| `paired_source` | 能找到源语言内容 | 语言质量、术语、占位符、HTML、SEO、语义一致性、漏译、多译、错译。 |
| `target_only` | 找不到源语言内容 | 语言质量、品牌语气、术语、禁用词、占位符语法、HTML、SEO、地区表达、合规关键词。不能可靠确认漏译、多译、错译。 |

源内容可以来自：

1. Shopify base locale。
2. 用户上传的参考文件。
3. 历史 translation job。
4. 用户指定的 reference content。
5. 其他可用 locale 的桥接翻译。

如果都没有，使用 `target_only`，不要阻断审计。

### 4.1 数据模型

每个审计对象必须记录审计模式和源内容可用性。

```json
{
  "audit_id": "mx-existing-2026-10-13",
  "audit_mode": "target_only",
  "market": "MX",
  "target_locale": "es-MX",
  "resource_type": "product",
  "shopify_resource_id": "gid://shopify/Product/123",
  "field_key": "title",
  "source_available": false,
  "source_origin": null,
  "source_locale": null,
  "source_text": null,
  "source_digest": null,
  "published_text": "Vestido de seda",
  "published_digest": "sha256:...",
  "status": "warning",
  "recommendation": "rewrite",
  "checks": [],
  "skipped_checks": ["semantic_equivalence", "omission", "addition"],
  "ai_review": null
}
```

`source_origin` 可选值：

| 值 | 说明 |
|---|---|
| `shopify_base` | 来自 Shopify base locale。 |
| `uploaded_reference` | 来自用户上传的参考文件。 |
| `history_job` | 来自历史 translation job。 |
| `bridge_locale` | 来自其他可用 locale 的桥接内容。 |
| `user_context` | 用户临时提供的参考内容。 |
| `none` | 没有源内容。 |

### 4.2 规则审计

#### 两种模式都执行

1. 空内容。
2. 目标语言检测。
3. 术语不一致。
4. locked / forbidden terms。
5. required regex。
6. 已知 token / placeholder 语法异常。
7. HTML 标签结构异常。
8. 长度限制。
9. SEO title / description 长度。
10. 重复模板。
11. 法务或合规关键词。
12. 明显不适合目标市场的表达。

#### 仅 `paired_source` 执行

1. 疑似未翻译。
2. placeholder 与源内容是否一致。
3. HTML 与源内容是否一致。
4. 语义一致性。
5. 漏译。
6. 多译。
7. 错译。
8. retranslate 建议。

#### 仅 `target_only` 执行

1. 记录 `source_available=false`。
2. 记录无法校验的语义项。
3. 降低整体置信度。
4. 不生成 `retranslate` 建议，除非用户后续补充源内容。
5. 使用 `rewrite`、`localize` 或 `manual_review` 表达修复建议。

### 4.3 可选 AI Review

AI Review 必须声明运行在哪种审计模式。

#### `paired_source` AI Review

输出结构化结论：

| 字段 | 说明 |
|---|---|
| `mistranslation` | 错译。 |
| `omission` | 漏译。 |
| `addition` | 多译。 |
| `tone_mismatch` | 语气不符。 |
| `brand_term_issue` | 品牌术语问题。 |
| `seo_issue` | 搜索关键词或 SEO 表达问题。 |
| `suggested_text` | 建议文本。 |
| `confidence` | 置信度。 |

#### `target_only` AI Review

禁止把以下结论作为确定性问题输出：

1. mistranslation。
2. omission。
3. addition。
4. semantic_equivalence_failure。

可以输出：

| 字段 | 说明 |
|---|---|
| `grammar_issue` | 语法或拼写问题。 |
| `clarity_issue` | 表达不清。 |
| `tone_mismatch` | 语气不符。 |
| `brand_term_issue` | 品牌术语问题。 |
| `locale_issue` | 不符合 MX / es-MX 表达习惯。 |
| `seo_issue` | 搜索关键词或 SEO 表达问题。 |
| `compliance_issue` | 合规或法务表达风险。 |
| `rewrite_suggestion` | 基于当前目标文本的重写建议。 |
| `confidence` | 置信度，必须低于有源内容时的同类结论。 |

AI Review 只产生建议，不直接修改 Shopify。

### 4.4 结果状态

每个 item 输出：

| 状态 | 含义 |
|---|---|
| `pass` | 当前模式下未发现问题。 |
| `warning` | 有风险，需要人工确认。 |
| `fail` | 当前模式下明确失败，建议修复。 |
| `missing` | 缺少目标翻译。 |
| `source_missing` | 没有源内容；这不是内容失败，而是审计能力限制。 |

每个 item 同时输出建议：

| 建议 | 含义 | 可用模式 |
|---|---|---|
| `keep` | 不处理。 | 两种模式。 |
| `fix` | 基于原文和已发布翻译做局部修复。 | `paired_source`。 |
| `retranslate` | 根据源内容重新生成翻译。 | `paired_source`。 |
| `rewrite` | 不依赖源内容，基于目标文本、品牌规则和上下文重写。 | `target_only`。 |
| `localize` | 只做 localization 调整。 | 两种模式。 |
| `manual_review` | 交给人工判断。 | 两种模式。 |
| `add_reference` | 建议用户补充源内容或参考内容。 | `target_only`。 |

### 4.5 交付文件

```text
shopify/existing-translations/{market}.jsonl
reports/existing-translation-audit-{market}.md
reports/existing-translation-audit-{market}.json
corrections/correction-plan-{market}.md
```

Markdown 报告开头必须显示：

```text
Audit mode: paired_source / target_only
Source availability: found / not_found
Source origin: shopify_base / uploaded_reference / history_job / bridge_locale / user_context / none
Unverifiable checks: semantic_equivalence, omission, addition
```

## 5. Correction Workflow

审计结果可以直接生成修复任务，但不能自动回写。

### 5.1 创建修复任务

用户确认后执行：

```text
根据 MX 审计结果创建 correction job。
```

BrandLab 生成：

```text
jobs/{job-id}/manifest.json
jobs/{job-id}/worklist.jsonl
jobs/{job-id}/translation-prompt.md
```

修复模式：

| 模式 | 输入 | 输出 |
|---|---|---|
| `fix` | source text + published text + audit issues | 局部修正后的翻译。 |
| `retranslate` | source text + guideline + glossary | 全新翻译。 |
| `localize` | source text 或 published text | 地区化调整。 |

### 5.2 审核与导出

修复任务复用现有治理链路：

```text
deterministic validation
→ trust score
→ review packet
→ human approve / reject / edit
→ export manifest
→ safe Shopify writeback plan
```

未批准内容永远不能进入回写。

## 6. Shopify Translation Discovery v2

当前 discovery 需要升级为“已有翻译发现”。

### 6.1 目标

1. 读取 canonical / base source content。
2. 读取目标 market/locale 的已发布翻译。
3. 按 Shopify resource、field、locale 配对。
4. 保留 source digest 和 target digest。
5. 保存原始 API response，便于排障。

### 6.2 覆盖资源

第一版优先支持：

1. Product。
2. Product SEO。
3. Collection。
4. Page。
5. Blog。
6. Article。
7. 常见 translatable metafields。

### 6.3 需要调研确认

实现前必须用测试店铺确认：

1. `translatableResource` 的准确字段。
2. `translationsRegister` 的输入结构。
3. `translatableContent.digest` 的使用方式。
4. Shopify locale 与 market 的关系。
5. Product title、description、SEO 的 translation key。
6. market-specific translation 是否有额外限制。
7. App 所需最小权限。
8. 回写后的 read-back 方式。

调研输出保存到：

```text
docs/SHOPIFY-TRANSLATION-API-NOTES.md
```

## 7. Safe Shopify Writeback

现有 `productUpdate` 不能继续作为多市场翻译写回方案，因为它更新的是资源默认字段。

### 7.1 新回写原则

1. 只写 approved translation。
2. 使用 Shopify Translation API。
3. 携带正确的 field digest。
4. 按 target locale / market 写入。
5. 回写前生成 mutation plan。
6. 回写必须经过两次确认：translation approve + writeback approve。
7. 执行使用独立 `--execute`。
8. 小批量执行。
9. 任一失败立即停止。
10. 执行后 read-back verification。
11. 保存 execution history 和 rollback source。

### 7.2 回写状态

| 状态 | 含义 |
|---|---|
| `planned` | 已生成回写计划。 |
| `approved` | 用户批准回写计划。 |
| `executing` | 正在执行。 |
| `executed` | 执行完成。 |
| `verified` | 已读回验证。 |
| `failed` | 执行失败。 |
| `rolled_back` | 已按 rollback source 回滚或待人工回滚。 |

## 8. Market Onboarding Workflow

新增命令或 Skill workflow：

```text
新增市场。
```

### 8.1 输入

必须确认：

1. market ID。
2. target locale。
3. Shopify locale。
4. source strategy。
5. translation mode。
6. review policy。
7. audit policy。

### 8.2 检查

1. Shopify market 是否存在。
2. Shopify language / locale 是否启用。
3. source language 是否等于 target language。
4. guideline 是否需要新建。
5. glossary 是否需要扩展。
6. 是否已有相同 market ID。
7. 是否会产生伪翻译任务。

### 8.3 输出

```text
brand.yaml 更新建议
guideline 创建建议
glossary 更新建议
market content plan
translation / localization 任务清单
review packet
下一步操作
```

`brand.yaml` 更新前必须给用户确认，避免直接改坏现有配置。

## 9. 实施里程碑

### M5.1 Market Registry v2

任务：

1. 扩展 `brand.schema.json`。
2. 扩展 `brand.yaml` template。
3. 支持 market ID 精确匹配。
4. 支持 `source_strategy`。
5. 支持 `translation_mode`。
6. 支持 `review_required`。
7. 支持 `audit_policy`。
8. 保持旧配置兼容。

验收：

1. 旧 `brand.yaml` 仍可加载，或给出明确迁移提示。
2. locale 相同但 market ID 不同的市场不会互相污染。
3. disabled market 不进入默认任务。
4. 缺少关键字段时给出可执行错误。

### M5.2 Shopify Existing Translation Discovery

任务：

1. 新增 Shopify translation discovery v2。
2. 尝试读取 base source；读取不到时降级为 target-only discovery。
3. 读取 published translation。
4. 有源内容时生成 paired translation snapshot。
5. 没有源内容时生成 standalone translation snapshot。
6. 支持导入 uploaded reference 和历史 job reference。
7. 保存 raw response。
8. 支持 fixture 测试。
9. 支持按 market、locale、resource type 过滤。

验收：

1. 不执行任何写操作。
2. Product、SEO、Collection、Page、Blog 至少有 fixture 覆盖。
3. 有源内容的每条记录包含 source digest 和 published digest。
4. 没有源内容的记录包含 `audit_mode=target_only` 和 `source_available=false`。
5. 现成 MX 店铺没有英文源内容时也能完成 discovery。
6. API 权限不足时给出安装引导。
7. uploaded reference / history job 命中时，记录 source origin，并写入 source text 与 source digest，使该条记录升级为 `paired_source`。

### M5.3 Existing Translation Audit

任务：

1. 新增 existing translation audit。
2. 支持 `paired_source` 和 `target_only` 两种模式。
3. 支持规则审计。
4. 支持可选 AI Review。
5. 生成 JSONL 和 Markdown 报告。
6. 输出 keep / fix / retranslate / rewrite / localize / manual_review / add_reference。
7. 支持从审计报告生成 correction plan。

验收：

1. 审计不修改 Shopify。
2. 每个字段都能给出明确状态、建议和审计模式。
3. 没有源内容时不执行漏译、多译、错译等语义一致性结论。
4. 用户可以看到问题数量、风险分布、建议处理方式和审计限制。
5. correction plan 只包含用户选择或明确推荐的 item。

### M5.4 Correction Job

任务：

1. 从 audit result 创建 correction job。
2. 支持 `fix`。
3. 支持 `retranslate`。
4. 支持 `localize`。
5. 支持 `rewrite`，用于 `target_only` 场景。
6. 有源内容时保留 original source、published text、audit issue。
7. 没有源内容时保留 published text、context、audit issue 和 AI review。
8. 复用 deterministic validation。
9. 复用 review packet 和 approval。

验收：

1. correction job 与普通翻译 job 不混淆。
2. 每条修复都能看到原翻译、审计模式和修复后内容。
3. `target_only` correction job 不要求源内容，但报告必须标明无法做语义一致性校验。
4. 未审批内容不能导出。
5. reject 后 item 回到审计待处理状态。

### M6.1 Market Onboarding

任务：

1. 新增 market onboarding workflow。
2. 检查 Shopify market / language / locale。
3. 生成 `brand.yaml` update plan。
4. 创建或推荐 guideline。
5. 更新或推荐 glossary。
6. 生成 market content plan。
7. 自动识别 translation vs localization-only。

验收：

1. 用户可以通过自然语言新增市场。
2. US / en 场景不会生成 English-to-English 翻译任务。
3. 新增市场必须显示完整 content plan。
4. 配置变更前必须确认。

### M6.2 Translation API 调研 spike

任务：

1. 用 Shopify 测试店铺验证 Translation API。
2. 记录 GraphQL query / mutation。
3. 记录 locale 与 market 的关系。
4. 记录权限和 userErrors。
5. 验证 read-back。
6. 更新 Shopify setup 文档。

验收：

1. 有可运行的最小 query / mutation。
2. 明确记录 unsupported fields。
3. 明确记录最小权限。
4. 不在正式店铺直接实验。

### M7.1 Safe Translation Writeback

任务：

1. 替换多市场场景下的 `productUpdate` 写回路径。
2. 使用 Translation API 写 approved translation。
3. 生成 writeback plan。
4. 支持 approval gate。
5. 支持独立 execute。
6. 支持 read-back verification。
7. 支持 failure stop。
8. 记录 rollback source。

验收：

1. 不会把 MX 翻译写入默认资源字段。
2. 不会覆盖未审批字段。
3. 回写失败时不继续后续批次。
4. 每个 executed field 都能回读验证。
5. history 中能还原谁在什么时候批准了什么内容。

### M7.2 多市场报告

任务：

```text
reports/market-translation-summary.md
```

3. **v0.3.0-rc：Safe writeback**  
   完成 Translation API 调研、writeback plan、execute、verification。

4. **v0.3.0：Market Onboarding**  
   发布新增 US / FR / DE / JP 等市场的完整引导。

## 11. 非目标

本轮不做：

1. 社媒平台 API 发布。
2. 图片自动生成或自动上传。
3. 多人管理后台。
4. 后端队列。
5. 自动翻译后无人工确认直接回写。
6. 覆盖所有 Shopify translatable resource；第一版只覆盖高频资源。

## 12. Definition of Done

v0.3.0 完成时必须满足：

1. 用户可以说“检查 MX 市场现有翻译”，得到结构化体检报告。
2. 每条内容都有 `pass / warning / fail / missing / source_missing` 和明确建议。
3. 现成 MX 店铺没有英文源内容时，可以走 `target_only` 体检和 rewrite correction。
4. 用户可以从体检报告创建 correction job。
5. correction job 走完整 validation、review、approval。
6. approved correction 可以生成安全回写计划。
7. 回写使用 Shopify Translation API，不再使用默认资源更新。
8. 用户可以说“新增 US 市场”，系统自动判断 translation 或 localization-only。
9. 所有 Shopify 写操作都有 history、rollback source 和 read-back verification。
